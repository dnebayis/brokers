# Coattail Brokers — Architecture

## Lifecycle

1. `CoattailBroker.mint(qty)` charges 0.001 ETH per NFT (owner may only lower it, down to 0 for a free mint), enforces the 2-NFT primary-mint wallet cap and creates an ERC-6551 account. Each ID is drawn without replacement from the sparse pseudo-random `1..1776` pool; the NFT starts inactive. The owner can also cut the sellable `mintCap` downward (never below what is minted; the 1,776-ID art space is fixed) and `refundAndBurn` a problem mint (owner-funded ETH back to the holder, token burned).
2. The owner approves and calls `activate(tokenId)`. Exactly 36,750 COAT is burned and the token becomes one active Booster share.
3. Sell-side COAT hook fees reach FeeSplitter. Its 80/10/10 outputs fund stock purchases, project treasury and the TWAP buyback burner.
4. `Booster.poke()` reads the signed route-ready basket, derives a Chainlink-protected minimum and calls `StockRouter` with each ETH slice.
5. StockRouter executes ETH→WETH→mid token→stock. The first hop is v3; the stock hop supports Rialto or v3. Both pool pairs and directions were verified when the owner installed the route.
6. Rewards accrue per active token ID. The current NFT owner calls `claim`; assets move to that NFT's ERC-6551 account.
7. A real NFT transfer deactivates the token. Pending entitlement follows the token ID; the buyer must burn again to reactivate.

## COAT launch

- Initial supply: 1,000,000,000 COAT, minted once to the liquidity distributor.
- Allocation: the full supply goes to a single-sided native-ETH/COAT v4 position. Exact Q96 rounding leaves 8,393 token-wei, which the launch script burns. There is no reserve/team balance.
- Price range: approximately 1e-8→1e-6 ETH/COAT, ticks 138000→184200, initialized at tick 184400 so the position starts 100% COAT.
- Fees: v4 LP fee 1%; immutable hook fee 1%. Buy-side hook COAT is burned; sell-side ETH is accrued for FeeSplitter.
- Launch protection is enforced in COAT at the canonical PoolManager transfer boundary: enable block rejects buys, then two capped blocks; no router whitelist exists.
- `AtomicV4Launcher` deploys the initializer-gated hook, initializes the pool, binds the current PositionManager token ID and mints that NFT directly to `PermanentV4LiquidityLocker` in one transaction. The locker has no owner, approvals, arbitrary call or liquidity-decrease path. Anyone can collect only accrued fees to immutable treasury.
- `pairedPrincipal()` derives position ETH principal solely from liquidity and current sqrt price. It excludes donations and fees. `graduated()` becomes true at 4.2 ETH without moving the pool.

Exact deployment constants and the activation-cost report are generated by `launch/compute_params.py` into `launch/launch-math.json`. `ForkLaunch.t.sol` checks the resulting calldata against the real Robinhood mainnet PositionManager.

## Trust and keys

- One hardware wallet owns Broker, Booster, StockRouter, Renderer, FeeSplitter and hook administration.
- Deployer, keeper and oracle/updater keys are separate. The keeper has no privileged role.
- Strategy updates are EIP-712 signed, epoch-monotonic and drift-bounded.
- On mainnet `allowUnguarded=true` is forbidden by Booster bytecode.
- The LP locker is ownerless and permanent.

## Route-ready boundary

The 194 canonical stock-token addresses are discovery input only. V1 basket generation uses the five
entries in `indexer/route-ready.mainnet.json` (AAPL, AMD, AMZN, COIN and CRCL). An entry is active
only after canonical address, both route pools, pool kind, stock feed and successful fork probe are
recorded. Other canonical assets are excluded until they meet those checks; V1 does not claim to buy
the entire canonical universe.

Fork note: Rialto Fermi freshness uses Arbitrum's L1 `block.number`, whereas Foundry initially injected the RPC L2 height into `BLOCKNUMBER`, producing a fork-only `ACF`. `ForkStockRoutes.t.sol` restores the live L1 value from each Fermi contract. All five manifest routes execute successfully against the real pools; latest combined probe: L2 block `36869820`.

## Release verification

- Unit/fuzz/regression suite plus 888-owner, two-random-ID-per-owner, 1,776-mint/activation/claim reconciliation.
- Required Robinhood mainnet fork for exact launch, hook fee/burn, locker custody, every stock route, buyback/TWAP and the complete reward path.
- After fork success, abandon legacy testnet addresses and execute a clean, resumable 888-owner testnet load. Every receipt must have status 1.
- Store deployment/address manifest, parameter hash, blocks/transactions, gas percentiles and exact supply/reward reconciliation.
